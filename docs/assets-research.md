# 에셋 조사 결과

조사일: 2026-07-28

> **현재 채택은 Tiny Swords다.** 아래 Kenney 관련 절은 2026-07-28 오전에 조사·통합했다가
> 같은 날 교체한 기록이다 — 사용자가 "프로토타입 같다, 진짜 타워 같은 걸로" 요청했고,
> Kenney TD 스프라이트는 원래 TD 포탑이라 성탑으로 안 읽혔다.
> 최종 결정은 문서 맨 아래 "교체: Tiny Swords" 절을 볼 것.
> 지운 내용이 아니라 남겨둔 이유: 무채색 + `color` 합성 틴트 기법과 그 측정값은
> 나중에 다른 에셋을 검토할 때 다시 쓸 판단 근거다.

## 판정 기준 (HANDOFF §7)

1. 상용 라이선스 (CC0 또는 상용 허용). 개인 사용 한정은 탈락
2. 탑다운 시점
3. 틴트 가능 — 파랑(P1)/빨강(P2)/회색(중립).
   조사·측정 당시 P2는 주황(`#fb923c`)이었고 2026-07-28에 빨강(`#f2555f`)으로 바꿨다.
   무채색 원본에 색을 입히는 방식이라 진영색을 바꿔도 에셋은 그대로다
4. 40~60px에서 읽힐 것

## 미결 사항에 대한 권고 — 레벨 축 vs 재고 축

HANDOFF §7 미결: 재고 구간(1-9 / 10-19 / 20-59 / 60) × 레벨(1~5) 을 둘 다 몸체에 담으면 20종.

**권고: 몸체는 레벨만 담는다. 스프라이트 5종으로 끝낸다.**

근거:
- 재고는 **이미 타워 중앙에 숫자로 정확히 표시된다.** 스프라이트가 같은 정보를 두 번 말할 이유가 없다
- 재고는 매 틱 변하는 값, 레벨은 매치당 최대 4번 변하는 값이다.
  자주 바뀌는 값에 몸체 교체를 걸면 화면이 계속 튄다
- 레벨은 이미 반지름에 연동돼 있어(`16 + level*3`) 몸체 5종과 축이 일치한다

재고는 몸체가 아니라 **베이스 링 채움 게이지**로 (`troops / TOWER_CAP` 만큼 원호를 채운다).
코드로 그리므로 에셋 0종. 60(상한) 도달은 링이 한 바퀴 다 찬 상태로 자연히 드러나므로
제거된 "만석 노란 깜빡 링"의 역할도 대체한다.

총 필요 스프라이트: **5종** (레벨 1~5), 진영은 틴트 3색.

### 타워 5종이 무채색인 근거 (측정값)

불투명 픽셀마다 `max(R,G,B) - min(R,G,B)` 를 재서 최대값을 봤다.

|---|---|---|---|
| 203 | 1388 | 0% | **0** |
| 226 | 1420 | 0% | **0** |
| 227 | 1390 | 0% | **0** |
| 228 | 1584 | 0% | **0** |
| 229 | 1224 | 0% | **0** |
| 204 | 1590 | 14.1% | 171 |

**203/226/227/228/229 는 spread 최대값이 0 — 완전 그레이스케일이다.**
곱연산 틴트로 어떤 색이든 깨끗하게 나온다. 이 팩에서 무채색 타워 몸체는 이 5개가 전부고,
필요한 레벨 수와 정확히 일치한다.

HUD 숫자 276~285 도 전부 maxSpread=0 이라 같은 방식으로 틴트된다.

### 레벨 순서를 정한 방법

인게임 지름(`(16 + level*3) * 2` = 38/44/50/56/62px)으로 축소해 P1 파랑·P2 주황·중립 회색
3색 틴트를 걸어 렌더한 뒤 눈으로 확인했다. 처음 순서(lv2=226, lv3=228)는 디테일이 역행해서
**228 ↔ 226 을 교체**했다. 최종은 민무늬 작은 것 → 민무늬 넓은 것 → 돌기 → 줄무늬 → 쌍포신 순으로
5단계가 38px에서도 구분된다.

## 렌더러 통합 (2026-07-28 완료)

`game/src/render/sprites.ts` 신규 + `renderer.ts` 수정.

### 색 입히는 방식 — `color` 합성

세 가지를 놓고 골랐다.

| 합성 | 결과 |
|---|---|
| `multiply` | 원본 명암 × 색. 원본이 회색(평균 140)이라 곱하면 어두워져 배경에 묻힌다. 실측했더니 주황 진영이 갈색으로 보였다 |
| `source-in` | 실루엣만 남기고 통째로 덮는다. 몸체 음영이 전부 날아간다 |
| **`color`** | 원본의 **명도는 두고** 색상·채도만 갈아끼운다. 결과 밝기가 원본 그대로다 |

`color` 를 쓴다. 이 선택 덕분에 **유닛 원본이 무채색일 필요가 없어졌다.**
`tankBody_sand`(평균 명도 163)를 베이스로 두고 진영색만 갈아끼운다.
무채색에 가까운 `tankBody_dark` 는 평균 명도가 77이라 어떤 색을 넣어도 검게 나와 탈락시켰다.

마지막에 `destination-in` 으로 원본 알파를 되씌우는 단계가 필수다. 없으면 `fillRect` 가
투명 영역까지 칠해 네모가 남는다.

### 여백 자동 제거

원본은 64×64 틀에 실제 그림이 36~46px만 든다(비율이 종류마다 다르다).

| 스프라이트 | 그림 경계 상자 | 틀 대비 |
|---|---|---|
| tower_lv1 | 36×36 | 56% |
| tower_lv2 | 46×36 | 72% |
| tower_lv3 | 38×46 | 59% |
| tower_lv4 | 38×41 | 59% |
| tower_lv5 | 38×46 | 59% |

그대로 그리면 레벨마다 크기가 제멋대로 보인다. 그래서 `sprites.ts` 가 **로드 시 알파 경계
상자를 재서 여백을 잘라낸 캔버스**를 만들어 둔다. 렌더러는 잘린 그림의 긴 변을 타워 지름에
맞춘다. 결과적으로 크기를 결정하는 건 `towerRadiusOf` 하나뿐이고 원본 여백은 개입하지 않는다.
에셋을 바꿔도 표를 고칠 필요가 없다 — 상자를 코드가 직접 잰다.

### 재고 링

`troops / TOWER_CAP` 만큼 호가 찬다. 반경은 `r + 8` — 처음 `r + 4.5` 로 뒀더니 몸체
스프라이트가 링을 먹어 게이지가 안 읽혔다. 경로 슬롯 점도 링을 피해 `r + 18` 로 내렸다.
링이 한 바퀴 다 차면 색이 흰색으로 바뀐다. 상한(60) 도달 = 중계기가 됐다는 신호다.

### 폴백

스프라이트가 아직 안 떴으면 예전처럼 원과 도형으로 그린다. 첫 프레임과 헤드리스 검증에서
화면이 비면 안 되기 때문이다.

### 검증

브라우저 패널이 안 열려 있어 스크린샷이 막힌다(§0). 대신 헤드리스로 확인했다:
동적 import → 봇 대 봇 1200틱(40초) 진행 → 오프스크린 캔버스에 `Renderer` 로 직접 렌더 →
`toDataURL` 로 이미지 회수. `requestAnimationFrame` 은 패널이 숨겨지면 멈추므로
대기에는 `setTimeout` 만 쓴다.

- 레벨 1~5 × 소유자 3종(P1/P2/중립) 15개 타워를 강제로 세워 전 조합 렌더 확인
- 재고 링이 12/24/36/48/60 에서 단계적으로 차고, 60에서 흰색으로 바뀌는 것 확인
- 전 에셋 경로 **HTTP 200**, 콘솔 에러 0
- **프레임당 0.292ms** (200프레임 평균). 통합 전 기준치 0.22ms, 60fps 예산 16.7ms

| 2. 탑다운 | 3/4 탑다운. 정탑다운은 아니지만 레퍼런스 게임과 같은 시점이고 성탑이 성탑으로 읽힌다 |
| 3. 틴트 가능 | **불필요** — blue/red/purple/yellow/black 진영 변형이 원본에 들어 있다 |
| 4. 40~60px 가독 | 통과. 실제 렌더로 확인 |

기준 3을 "틴트 가능"이 아니라 "진영 분리 가능"으로 읽으면 이 팩이 더 낫다.
색을 코드로 안 만드니 결과가 아티스트가 의도한 색 그대로다.

### 추출 규칙 (`scratchpad/export_ts.ps1`)

- 원본은 그림 주위 투명 여백이 크다 → 알파 경계로 잘라서 내보낸다
- **유닛 6프레임은 프레임마다 자르면 달릴 때 스프라이트가 튄다.** 6프레임 **합집합** 상자로
  잘라 전부 같은 크기로 맞춘다. 다시 뽑을 일이 있으면 이 규칙을 지킬 것

### 렌더러 배치

3/4 시점이라 이전처럼 원 안에 넣지 않는다. 바닥을 타워 지점에 대고 세운다.

- 크기: 높이 상한 `2r × 1.85`, 폭 상한 `2r × 1.75` 중 **빡빡한 쪽**.
  높이만 맞추면 성채(312×208)가 지름의 2.8배까지 벌어져 경로를 덮는다
- 재고 게이지: 정원이면 링이 건물을 관통한다 → **발치에 눕힌 타원**(`GROUND_SQUASH = 0.42`)
- 재고 숫자: 발치 배지. 건물 벽돌 무늬 위에 그냥 쓰면 묻힌다
- 유닛: 사람 모양이라 회전시키면 옆으로 눕는다 → **좌우 반전만.**
  러닝 사이클 위상을 유닛 id로 어긋내 전부 같은 발로 안 뛰게 했다

### 배포물

`game/public/assets/` 28파일 **0.134MB** (건물 15 + 유닛 12 + 라이선스 1).
원본 전체는 `assets-src/` 1925파일 15.4MB — `game/` 밖이라 빌드에 안 실린다.

### 검증

- 레벨 1~5 × 소유자 3종 15개 강제 배치 렌더 확인
- 봇 대 봇 60초 진행 화면 확인
- 전 경로 HTTP 200, 콘솔 에러 0
- **프레임당 0.591ms** (Kenney+틴트 시절 0.330ms, 예산 16.7ms 대비 3.5%)

헤드리스 검증 함정 하나 추가: **브라우저 패널이 숨겨져 있으면 `window.innerWidth`가 0**이라
`Renderer.resize()` 가 1px 캔버스를 잡고 화면이 비어 나온다. 검증 코드에서
`Object.defineProperty(window, 'innerWidth', { value: 1280 })` 로 고정할 것.
